# V1-I-R3H-R2 provider execution closure

R3H-R2 turns the intelligence catalog into typed standard packages. A package
is connectable only when its manifest says `CONTROLLED_PROTOCOL_TESTED`; a
catalog-only or externally unproven entry remains informational and cannot be
connected as a ready provider.

## Shared execution path

Named OpenAI-shaped services use one `OpenAICompatibleProvider` with a fixed
package preset. The preset owns the official HTTPS endpoint, model-list path,
chat path, authentication header, and safe headers. The generic
`openai-compatible` package remains separate and requires an explicit HTTPS
base URL (or trusted literal loopback metadata for local use).

Anthropic and Gemini use typed native adapters because their request and model
list shapes are not OpenAI chat-completions contracts. Azure keeps deployment
and API-version routing in its enterprise package. Vertex keeps project,
region, and a trusted OAuth-token resolver typed. Bedrock uses a concrete AWS
Signature Version 4 signer seam; AWS keys never enter provider metadata.

All adapters use the existing `CredentialVault` reference boundary, bounded
model discovery, `ExactRouteIdentity`, `ProviderRegistry`,
`ModelKnowledgeService`, policy, usability, and routing owners. Remote
redirects are never followed for credential-bearing requests, errors are
normalized to bounded reason classes, and provider response text is never
treated as trusted instructions.

## Support truth

The 28-row support matrix is generated by `provider_support_matrix()`. The
P1-P28 execution matrix is generated by `provider_execution_matrix()` and
keeps catalog, package, adapter, controlled protocol, discovery, onboarding,
routing, and physical-validation states separate.

The following are source-executable and controlled-fixture tested in this
closure: OpenAI, Anthropic, Google Gemini, Cohere, AI21, xAI, Mistral,
DeepSeek, OpenRouter, GroqCloud, Together AI, Fireworks AI, Cerebras Cloud,
SambaNova Cloud, NVIDIA hosted NIM, Perplexity, Alibaba DashScope/Qwen,
Moonshot/Kimi, Zhipu/GLM, Baidu Qianfan, Tencent Hunyuan, ByteDance Volcano,
Azure OpenAI, Amazon Bedrock, Google Vertex AI, and generic
OpenAI-compatible.

MiniMax remains catalog-only because current official protocol details were not
established safely in this closure. TypeSafe/Jev remains the explicitly
external, typed decision-provider boundary with the existing local fallback;
no remote protocol is fabricated for either row.

## Discovery and zero-cloud behavior

Dynamic model lists register every bounded returned model, including a model
that was absent on the previous refresh, without a central model allow-list.
Only provider-reported metadata is copied; price, context, modality,
lifecycle, and capability facts remain unknown when not returned. Newly
discovered routes inherit existing policy and usability gates.

Startup does not probe providers merely because they are in the catalog.
Safe Mode does not authenticate or discover remotely, and the local runtime
continues to operate without cloud credentials.
