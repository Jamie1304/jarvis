# Transparent memory controls

JARVIS exposes memory controls through the typed application service
`MemoryControlService`. Desktop, voice, and future presentation clients receive
the same `MemoryControlEntry` view and do not access SQLite stores directly.

The facade does not create a third memory authority. It delegates durable-memory
operations to `SQLiteMemoryStore` and user facts/preferences to `UserModelStore`.
Each entry carries its domain, stable ID, workspace (when applicable), category,
belief, deterministic explanation, safe provenance, source, confidence, creation /
update / verification timestamps, supersession lineage, retention, sensitivity,
and current retrieval state.

## Filtering and display

`MemoryControlQuery` supports bounded filters for workspace, category, sensitivity,
source, updated-time recency, and confidence. Secret sensitivity is never an
allowed presentation filter. Secret-like source references are redacted, and
CredentialVault contents are never read or exported by this service.

The `why` field is generated by application code from stored provenance and origin;
it is not model-written justification. External/tool/web provenance remains
labelled data and does not become a trusted personal fact.

## User actions

The application facade provides typed actions for correction, individual deletion,
category forgetting, structured export, retention changes, pause/resume learning,
marking a record explicit, and requesting re-verification. Corrections preserve
the owning store's lineage/audit rules. A durable-memory correction creates a new
record and supersedes the old record; a user-model correction creates a new
revision in the user-model authority. These actions are unavailable as direct
model tools.

Learning pause is durable in both authoritative stores. It blocks new automatic
long-term memory and non-user user-model writes while leaving existing retrieval
and trusted user corrections available. Re-verification requests are durable
pending requests, not verification evidence; only later trusted evidence can
change verification or confidence.

Retention changes update the authoritative record and therefore affect expiry and
future retrieval. Deletions and category forgetting deactivate/remove records in
the owning store. Exports are bounded structured data and never include raw Vault
secrets.

Tests in `tests/test_memory_control.py` cover filtering, explanations, redaction,
correction/retrieval, retention, deletion, category forgetting, pause/resume,
restart persistence, re-verification, and the UI-facing application facade.
