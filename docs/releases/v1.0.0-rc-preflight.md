## Architecture and state ownership

JARVIS remains a minimal adaptive core. No product-specific integration catalog,
donor runtime, website-specific browser path, product-specific trigger, or
fixture-specific production adapter was added. New capability acquisition still
follows `DISCOVER -> ADOPT -> REUSE -> BUILD`.

The authoritative state map has one owner for each current durable domain:

- adoption/setup decisions and `AdoptionAttestation`: `SQLiteSetupStore`;
- compensation lifecycle: `CompensationStore`/`CompensationService`;
- UI simulation/certification evidence: trusted `UISimulationAttestation`, with
  reference/digest in the capability lifecycle certification record;
- rendered UI artifacts: `ArtifactStore`, not certification state.

No competing writer or separate database is introduced by these remediations.
