## POST-RC-CI REMEDIATION

The previous immutable RC remains failed and is never treated as approved:

```text

GitHub CI runs: 32835066972, 32835070462
Failure: quality / seven sandbox tests exited before their first IPC response
```

The failure was reproduced as a test-boundary defect: generic protocol/lifecycle
tests used the Windows `RESTRICTED_TOKEN` diagnostic launcher through their
shared helper. Those tests did not require restricted-token semantics, but
therefore depended on cross-version restricted Python bootstrap behavior. The
old RC had no startup diagnostics, so the native child-bootstrap subcause is
not claimed as proven from that historical run. The remediation moves generic
tests to explicit `JOB_OBJECT_ONLY` diagnostic mode, retains a focused
restricted-token test, and adds bounded `SandboxStartupDiagnostics` for early
child exit. The production executable contract remains capability-free
AppContainer plus scoped ACLs, explicit handles, and Job Object; restricted-token
and Job-only modes remain non-certifiable.

donor runtime, website-specific browser path, product-specific trigger, or
fixture-specific production adapter was added. New capability acquisition still
follows `DISCOVER -> ADOPT -> REUSE -> BUILD`.

The authoritative state map has one owner for each current durable domain:
