## R4 production capability-growth remediation

The previous gap was that production construction selected unavailable package
generation/runtime seams. The current mutable tree composes one generic path:

```text
ProviderRegistry -> ProviderRouter -> bounded AgentLoop
 -> AgentRuntimeCapabilityGenerator -> ProductionPackageStore
 -> PackageReviewer/PackageCertifier -> AppContainer sandbox
 -> SetupConductor/typed ProvisioningEngine
 -> PackageActivationService -> sealed ToolRegistry activation port
 -> GeneratedCapabilityToolAdapter -> PermissionBroker -> package runtime
 -> trusted Shadow/Canary attestation -> ACTIVE/hot-load -> VerificationEngine
```

The production acceptance test uses a randomized capability and a fake provider
registered through the normal registry; it does not use `RuntimeTestFixture`,
fixture-specific production adapters, direct ACTIVE writes, donor runtimes, or
product-specific branches. The test asserts that the randomized typed action is
selected by PlanningEngine, resolved by ToolRegistry, passed through
PermissionBroker, executed by the package runtime, schema-validated, and
accepted by VerificationEngine before the original goal completes. Package
bytes are hash-addressed and external to the lifecycle database;
lifecycle/certification/activation truth remains in
`SQLiteCapabilityLifecycleStore`. A missing routable model/provider fails
closed as `WAITING_FOR_MODEL_PROVIDER` rather than selecting an unavailable
generator.
