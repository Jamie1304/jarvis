## Scope

This sweep reconciles the v1 claims with the normal `ApplicationRuntime.create()` graph.
The historical R4 status is not rewritten. `RuntimeTestFixture` remains valid for
lower-level deterministic contracts, but it is not production-composition evidence.

The production capability-growth test uses a randomized synthetic capability, a provider
registered through `ProviderRegistry`, and a temporary application-data directory. It does
not use `RuntimeTestFixture`, direct `ACTIVE` writes, product-specific adapters, donor
runtimes, or external systems.

## Claim boundary

The strong self-expansion claim is retained only with these prerequisites: a configured
routable model/provider, supported Windows generated-process containment, sufficient local
resources, and normal user authority where an effect requires it. It does not mean every
arbitrary integration will succeed. Voice/TTS hardware, browser companions, external MCP,
physical presentation, cross-machine credential migration, VM/kernel isolation, and signed
self-update execution remain optional or separately gated.
